Actions

MAPS provides various actions that are triggered when a rule violation occurs. Some of the actions are simple notifications such as RASLog and simple network management protocol (SNMP) traps. Other actions are complex, such as port toggle or port fencing.

For example, if you define a rule with an SNMP action and a violation of that rule occurs, the switch sends that SNMP trap to all SNMP trap receivers configured on the switch.

MAPS Actions

Action
Description

DECOM

The port decommissioning (DECOM) action provides an automated mechanism to remove an E_Port or F_Port from use.

The DECOM action automatically takes ports offline when the configured threshold in a given rule is exceeded. Port decommissioning takes a port offline without a loss of traffic. This action is disabled by default. Port decommissioning and port fencing can be configured only for the port health monitoring systems where decommissioning is supported.

Port decommissioning cannot be configured by itself in a MAPS rule or action. Port decommissioning requires port fencing to be enabled in the same rule.

EMAIL

An Email action sends information about a switch event to one or more specified Email addresses. The Email alert specifies the threshold and describes the event similar to an error message. For more information, see Email Alerts and Email Delivery Monitoring.

The Email notifications generated by system policy rules take precedence over global configurations. If you have a specific requirement to modify the behavior of the system rules, you can create custom rules.

FENCE

The port fencing action takes the ports offline when the user-defined thresholds are exceeded. This action immediately takes ports offline, which might cause a loss of traffic.

If fencing is part of the overall switch configuration, it occurs anytime the port fails. If fencing is part of a rule, the port is fenced if triggered. Multiple rules can have port fencing as an action, and fencing occurs if any of the rules are triggered.

FMS

A FICON Management Server (FMS) notification is sent to the FICON management service as an action from MAPS.

The FICON management service uses MAPS events to create a health summary report. Rules with a FICON notification action are part of all four default policies.

FPIN

Fabric Performance Impact Notification (FPIN) is a default MAPS action. The action enables FPI event reporting to the fabric members that are participating in fabric notifications. The MAPS FPIN action triggers fabric notifications when the following performance impact conditions occur in a fabric:
  • Congestion – Credit-stall and oversubscription conditions are detected on an F_Port.
  • Link Integrity – Signal integrity degradation issues such as CRC and ITW are detected on an F_Port.
The following MAPS monitoring systems support FPIN:
  • CRC
  • ITW

For more information about fabric notifications, refer to the "Fabric Notifications" section in the Brocade Fabric OS Administration Guide.

The FPIN action is a default MAPS action and this action is supported on Access Gateway (AG) switches. FPIN action is not supported on IPS LS.

HA_RECOVER

When the HA_RECOVER action is executed, the HA failover action (using the hafailover command) is performed on Brocade Directors, and the HA reboot action (using the hareboot command) is performed on Brocade Switches.

RASLog

The RASLog action adds an entry to the RASLog message event log for an individual switch. The RASLog message stores infrequent event information and errors, but the action does not actively send alerts. The RASLog message acts as a centralized logging mechanism for Fabric OS and covers the following:
  • Error detection
  • Reporting
  • Presenting data for administrators

Enable the RASLog action globally on the logical switches as required. In Fabric OS v10.0.x, the RASLog action is automatically enabled for all system policy rules if the associated rule is configured with the RASLog action. The RASLog notifications generated by system policy rules take precedence over global configurations. If you have a specific requirement to modify the behavior of the system rules, you can create custom rules.

RE_BALANCE

The RE_BALANCE action returns the port group state to the balanced state when the port group is in the im_balance state. Administrators can configure an automatic re_balance action or they can use the devicelogin command to perform the RE_BALANCE action manually.

SDDQ

The Slow-Drain Device Quarantine (SDDQ) action automatically moves the traffic that is destined to the F_Port connected to a slow-draining device to a low-priority virtual channel. This action does not disable the port, but it reduces the effect of its latency on other flows in the fabric. SDDQ actions can be configured to only monitor rules, such as, the DEV_LATENCY_IMPACT state of IO_PERF_IMPACT and IO_FRAME_LOSS.

Note: The SDDQ and Toggle actions are mutually exclusive.

SFP_MARGINAL

The SFP_MARGINAL action places the SFP into a marginal operating state. When a threshold is triggered, the SFP transceiver status changes to a marginal status. The port SFP transceiver measurements include current, receive power, transmit power, voltage, temperature, and power on hours. The SFP_MARGINAL action is enabled by default. The SFP_MARGINAL action is available for SFP transceiver measurements in the Port Health category.

SNMP

When managing a high volume of messages from multiple switches, consolidating them in a single location and using a graphical user interface (GUI) for viewing can be beneficial. In this scenario, SNMP notifications can be the most efficient notification method. You can avoid logging in to each switch individually, as you would have to do for error log notifications.

SNMP performs an operation that is called a trap, which notifies a management station using SNMP when specific events occur on a switch.

An SNMP trap delivered to the SNMP management station contains the following information:
  • Name of the element with the counter that registered an event
  • Event type
  • Value of the counter that exceeded the threshold
  • State of the element that triggered the alarm
  • Source of the trap

You must configure the software to receive trap information from the network device. You must also configure the SNMP trap receiver on the switch using the snmpConfig command to send the trap to the management station.

Enable the SNMP action globally on the logical switches as required. In Fabric OS v10.0.x, the SNMP action is automatically enabled for all system policy rules if the associated rule is configured with the SNMP action. The SNMP alerts generated by system policy rules take precedence over global configurations. If you have a specific requirement to modify the behavior of the system rules, you can create custom rules.

SW_CRITICAL

The SW_CRITICAL action sets the state of the affected switch in the MAPS dashboard display to CRITICAL. This action does not bring the switch down, but it affects what is displayed in the dashboard.
Note: This action is valid only in the context of rules that are related to the Switch Status Policy.

SW_MARGINAL

The SW_MARGINAL action sets the state of the affected switch in the MAPS dashboard to marginal. This action does not affect the actual state of the switch, but it affects what is displayed in the dashboard.

Note: This action is valid only in the context of rules that are related to the Switch Status Policy.

TOGGLE

The port toggling (TOGGLE) action temporarily disables a port and then re-enables it. The action allows the port to reset and helps to restore the expected fabric performance. It attempts to recover the congestion conditions that are caused by credit-stalled or oversubscribed links using the FPI (DEV_LATENCY_IMPACT) measure.

UNQUAR

The UNQUAR (unquarantined) action is used to unquarantine the ports automatically during the following conditions:
  • When a port is moved to the quarantined state, user intervention is required to move the port back to the normal state.
  • When the Slow-Drain behavior is infrequent.

For more information about quarantining, see Slow-Drain Device Quarantining.

The following MAPS actions are configured globally by default:
  • SW_CRITICAL
  • SW_MARGINAL
  • SFP_MARGINAL
  • FPIN (FPIN is the default action for regular LS, but not for IPS LS.)
  • HA_RECOVER

In IPS LS, FC F_Ports are not supported. Therefore, the following F_Port-related actions cannot be configured:
  • FPIN
  • RE_BALANCE
  • SDDQ
  • UNQUAR
  • FMS
