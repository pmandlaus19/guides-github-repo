IO Latency

The IO Latency category monitors metrics that are associated with the I/O operations between an initiator and a target.

The following monitoring systems monitor IO latency statistics for each flow.

IO Latency Category Parameters – Flow

Monitoring System

Description

MAX_RD_PENDING_IO

Describes the maximum read pending I/O per ITL/ITN/VITL/VITN on flows and target ports.

MAX_WR_PENDING_IO

Describes the maximum write pending I/O per ITL/ITN/VITL/VITN on flows and target ports.

RD_1stDATA_TIME

Describes the time taken to receive the first read data frame from the target.

RD_STATUS_TIME

Describes the total completion time for the read I/O request.

RD_PENDING_IO

Describes the number of pending read I/O requests for IT flows.

WR_1stXFER_RDY

Describes the time taken to receive WRITE transfer ready frame from the target.

WR_STATUS_TIME

Describes the total completion time for the write I/O request.

WR_PENDING_IO

Describes the number of pending write I/O requests for IT flows.

RD_1stDATA_TIME_VIOL

Describes the violation percentage of read IOs that exceeded threshold of first response time from the target.

WR_1stXFER_RDY_VIOL

Describes the violation percentage of write IOs that exceeded threshold of first response time from the target.

RD_STATUS_TIME_VIOL

Describes the violation percentage of read IOs that exceeded threshold of IO completion time.

WR_STATUS_TIME_VIOL

Describes the violation percentage of write IOs that exceeded threshold of IO completion time.

If the default policy does not meet your requirements, you can clone an existing default policy and create a custom rule. When you create a custom rule, you must account for the constraints that are associated with each parameter of that rule. The following information is provided to help you effectively manage MAPS features, with each component designed for a specific purpose.
  • Monitoring Systems Matrix
  • States Severity
  • MAPS Default Rules
  • MAPS Default Groups
For more information, refer to the Brocade Fabric OS MAPS Rules Reference Manual.

Rule Data

The following example shows the default rules to monitor the I/O latency. This rule triggers the configured actions when the first data transfer for a write I/O request reaches greater than 1750 microseconds in a 10-seconds polling period.

Rule Data:
----------
RuleName: defWR_1stXFER_RDY_17500
Condition: sys_flow_monitor_nvme(WR_1stXFER_RDY/10SEC>1750)
Actions: RASLOG,SNMP qt=10 min
Associated Policies: dflt_aggressive_policy
