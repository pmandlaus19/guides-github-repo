Fabric Performance Impact

Fabric Performance Impact (FPI) monitoring utilizes MAPS policies to detect and assess port-level latency, frame loss, and throughput within a fabric. This monitoring helps to identify congestion and oversubscription issues. The FPI detects the performance impacts automatically and provides alerts based on the severity of the impact that is caused by credit-stalled devices and congested ports.

The following table lists the monitoring systems in this category:

Fabric Performance Impact Category Parameters

Monitoring System

Description

DEV_LOGIN_DIST

Describes the port group state. This monitoring system has the following threshold values:
  • BALANCED – All ports in the group have close to an equal number of devices that are connected to them.
  • IMBALANCED – At least one port in the group does not have any connected devices or has more or less than two connected devices than the rest of the ports in the group.
  • BALANCE_FAILED – MAPS performed the re_balance action but failed to rebalance the group.

DEV_LATENCY_IMPACT

Describes the port congestion can cause high traffic latency, which is monitored in two states:
  • IO_PERF_IMPACT: Indicates moderate latency that degrades fabric performance.
  • IO_FRAME_LOSS: Signifies severe latency or frame loss, resulting in significant backpressure and performance impact.

IT_FLOW

Describes the initiator to target flow ratio. If any device is zoned to 124 or more zones, then the device is not monitored.

PORT_BANDWIDTH

Describes the port oversubscription states in FC ports or ETH ports. In addition, this monitoring system has the following threshold values:

  • OVERSUBSCRIBED – This state shows that the port is in the oversubscription condition.
  • OVERSUBSCRIPTION_CLEAR – This state indicates whether the oversubscription state is cleared or not.

RX

Describes the percentage of port bandwidth being used by received and incoming (RX) traffic on FC or ETH ports. For example, if the port speed is 10G and the port receives 5G of data in one second, then the percentage of RX utilization is 50% (5G × 100/(10G × 1 second)). For a controller trunk port, this incoming traffic percentage indicates the RX percentage for the entire trunk.

TX

Describes the percentage of port bandwidth being used by transmitted, outgoing (TX) traffic on FC or ETH ports. For example, if the port speed is 10G and the port sends 5G of data in one second, the percentage of TX utilization is 50% (5G × 100/(10G × 1 second)). For a controller trunk port, this outgoing traffic percentage indicates the TX percentage for the entire trunk.

UTIL

Describes the percentage of the individual FC port or ETH port (or trunk) bandwidth being used at the time of the most recent poll.

If the default policy does not meet your requirements, you can clone an existing default policy and create a custom rule. When you create a custom rule, you must account for the constraints that are associated with each parameter of that rule. The following information is provided to help you effectively manage MAPS features, with each component designed for a specific purpose.
  • Monitoring Systems Matrix
  • States Severity
  • MAPS Default Rules
  • MAPS Default Groups
For more information, refer to the Brocade Fabric OS MAPS Rules Reference Manual.

Rule Data

The following example shows the default rules to monitor the FPI. This rule shows the frequency that a port is counted as oversubscribed.

RuleName: defALL_PORTS_OVERSUBSCRIBED
Condition: ALL_PORTS(PORT_BANDWIDTH/NONE==OVERSUBSCRIBED)
Actions: RASLOG,SNMP,FPIN qt=15 min
Associated Policies: dflt_aggressive_policy, dflt_moderate_policy, dflt_conservative_policy
