Port Health

The Port Health category monitors port statistics, SFP diagnostic parameters, and physical Fibre Channel (FC) and Ethernet ports. This monitoring category helps to take action based on the configured thresholds and actions. You can configure thresholds by the port type, and you can apply the configuration to all ports of the specified type.

Port Health Category Parameters

Monitoring System

Description

C3TXTO

Describes the number of Class 3 discard frames due to timeouts.

ROUTING_ERR
Describes the monitoring system that is used for a timely identification of frame drops due to the following factors:
  • Frames that are not routable
  • Frames with unreachable destinations
The bad routes are identified only when the fabric is stable, and the errors during a fabric reconfiguration are ignored.
CRC

Describes the number of Cyclic Redundancy Check (CRC) errors on FC or ETH ports in IPS LS indicate potential hardware issues, often caused by noise or interference during frame transmission.

DEV_NPIV_LOGINS

Monitors the number of NPIV logins on a port.

ITW

Describes the number of times an invalid transmission word (ITW) error occurs on an FC port or an ETH port. A word that is not transmitted successfully results in encoding errors. Invalid word messages usually indicate a hardware problem.

LF

Describes the number of times a link failure (LF) occurs on offline ports, or sends or receives the Not Operational Primitive Sequence (NOPS). Both physical and hardware problems can cause link failures. Link failures also frequently occur due to a loss of synchronization or a loss of signal.

LOSS_SIGNAL

Describes the number of times that a signal loss occurs while FC or ETH port is coming up and failed. Signal loss indicates that no data is moving through the port. A loss of signal usually indicates a hardware problem.

LOSS_SYNC

Describes the number of times a synchronization error occurs on the port. Two devices failed to communicate at the same speed. A link failure always accompanies synchronization errors. Loss of synchronization errors frequently occurs due to a faulty SFP transceiver or cable.

LR

Describes the number of link resets (LRs) on a port.

PE

Describes the number of times a protocol error (PE) occurs on a port. Occasionally, PEs occur due to software glitches. Persistent errors generally occur due to hardware problems.

STATE_CHG

Describes the changes in the state of the FC or ETH port due to any of the following reasons:

  • The port has gone offline.
  • The port has come online.
  • The port is faulty.
CURRENT

Describes the amperage that is supplied to the SFP transceiver in milliamperes. Alerts on current metric indicate potential hardware failures.

RXP

Describes the power of the incoming laser (receive power) in microwatts. This value is used to help determine if the SFP transceiver is in good working condition. If the value is lower or greater than the threshold, there is a potential problem with an SFP.

SFP_TEMP

Describes the temperature of the SFP transceiver in degrees Celsius. High temperatures indicate that the SFP transceiver could be in danger of damage.

TXP

Describes the power of the outgoing laser (transmit power) in microwatts. This value is used to determine if the SFP transceiver is in good working condition. If the value is lower or greater than the threshold, there is a potential problem with an SFP.

VOLTAGE

Describes the voltage that is supplied to the SFP transceiver in millivolts. If this value exceeds the threshold, the SFP transceiver is deteriorating.

PWR_HRS

Describes the number of hours that an SFP transceiver has been powered up.

ENCR_BLK

Describes the encryption blocks.

ENCR_DISC

Describes the encryption discard.

ENCR_SHRT_FRM

Describes the encryption short frames.

If the default policy does not meet your requirements, you can clone an existing default policy and create a custom rule. When you create a custom rule, you must account for the constraints that are associated with each parameter of that rule. Rule Data

The following example shows the default rules for monitoring port health. These rules trigger the configured actions when the number of CRC errors reaches the threshold.

Rule Data:
----------
RuleName: defALL_HOST_PORTSCRC_21
Condition: ALL_HOST_PORTS(CRC/MIN>21)
Actions: RASLOG,SNMP,FPIN
Associated Policies: dflt_conservative_policy
