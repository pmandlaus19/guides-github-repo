Email Delivery Monitoring

MAPS monitors various system statistics and when it detects a rule violation, it can trigger various alert actions, including EMAIL notifications, similar to how RASLog is used.

The SMTP MTA (Simple Mail Transfer Protocol Mail Transfer Agent) acts as the intermediary that relays emails sent from the Brocade switch to the configured recipient email addresses. The MTA handles the actual transfer of the email message over the network using the SMTP protocol.Use the relayconfig command to configure the SMTP server. MAPS email delivery uses the configured relay server information for relaying emails to the configured recipient address.

Note: When secure SMTP mode is enabled, the switch establishes a connection with the SMTP server on default port 587 for TLS. When secure SMTP is disabled, the default SMTP port 25 is used in a non-secure mode.

When you upgrade to Fabric OS v10.0.x, if you have not configured the EMAIL action and relay host configurations, secure SMTP is disabled as shown in the following example:switch:admin> mapsconfig --show
Configured Notifications: SW_CRITICAL,SW_MARGINAL,SFP_MARGINAL,FPIN,HA_RECOVER
Mail Recipient: Not Configured

switch:admin> relayconfig --show
Relay Host:
Relay Domain Name:
Secure SMTP: Disabled








































































































Note:
  • If you have enabled secure SMTP without importing the SMTPS CA certificate, the upgrade to Fabric OS v10.0.x is blocked. Ensure that the SMTPS CA certificate is imported before upgrading.
  • When you upgrade from pre-Fabric OS v10.0.x to Fabric OS v10.0.x, the SMTP mode remains in the disabled state.

After you have upgraded to Fabric OS v10.0.x, if you have not configured any relay host server (using relayconfig) and Email (on any LS or VF), you can use the mapsconfig --actions command, and include EMAIL as one of the actions. The following example enables EMAIL as an available action and simultaneously enables secure SMTP:switch:admin> mapsconfig --actions SNMP,RASLOG,EMAIL,SDDQ

switch:admin> mapsconfig --show
Configured Notifications:       EMAIL,SW_CRITICAL,SW_MARGINAL,SFP_MARGINAL,HA_RECOVER


switch:admin> relayconfig --show
Relay Host:
Relay Domain Name:
Secure SMTP:                    Enabled


2025/07/02-09:20:12 (GMT), [MAPS-1019], 1701, FID 128, INFO, new_switch_name, MAPS secure SMTP mode is Enabled.

2025/07/02-09:20:12 (GMT), [MAPS-1130], 1702, FID 128, INFO, new_switch_name, Actions EMAIL configured.

















































































































































































































Only one email failure RASLog is generated within an hour for every configured email address. Another RASLog that is sent every hour, which indicates the total number of failures in one hour. Sending only one RASLog avoids generating too many RASLog failure messages if there is an email server problem or network issues.

In MAPS, emails are sent using the sendmail command in Linux. In an erroneous scenario, an email can be sent from a system, but it might not be successfully delivered to the destination email server. The initial steps to debug such problems are to check the following items:
  • Whether the network is running
  • Whether the routing tables are configured correctly
  • Whether DNS is configured correctly

Examples of RASLog Messages

The following example shows a RASLog that is generated when the sendmail command fails to send an email from the switch.

2025/07/02-19:49:00, [MAPS-1206], 1468, SLOT 6 CHASSIS, INFO, dcx_178, A MAPS notification sent from the switch to abc@company.com could not be delivered to the mail server.

The following example shows a RASLog that is generated every hour to indicate the number of failures encountered in one hour. This RASLog is generated only if more than one failure is encountered for any failed address during the one hour.

2025/07/02-20:49:00, [MAPS-1206], 1468, SLOT 6 CHASSIS, INFO, dcx_178, There were 12 or more notifications that could not be delivered in the last one hour.
