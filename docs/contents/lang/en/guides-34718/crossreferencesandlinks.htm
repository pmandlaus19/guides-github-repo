Using conref and conkeyref for Reuse

The conref attribute enables reuse by referencing existing elements from other topics.

The conkeyref mechanism allows referencing through keys, enabling flexible content handling.

Example:
          <p conref="sharedContent.dita#sharedContent/shared_para_intro"/>
        





























Tip: Verify topic IDs across your project to avoid broken references.

Conditional Text and Filtering

DITA supports conditional processing through attributes such as audience, platform, and product.

Conditional processing is configured at publishing time using DITAVAL files.

For more details, see Content Repositories and Governance.

Content Repositories and Governance

Repository workflows provide:
  • Version control and historical tracking
  • Collaborative editing and review
  • Improved reuse via shared libraries

Map Based Reuse

DITA maps provide structure for assembling deliverables and organizing topics.

Example:
          <topicref href="install.dita"/>
          <topicref href="configure.dita"/>
        












































Always follow best practices when implementing reuse to ensure consistency.

Best Practices Overview

When implementing reuse strategies, consider the following recommendations:

  • Define and maintain a global keyspace for key management.
  • Establish ownership rules to prevent accidental overwriting.
  • Use clear filenames and IDs for readability.
  • Store shared content in a dedicated resources or common directory.

Summary

DITA supports powerful reuse through conrefs, keyrefs, and repository workflows.

For deeper information, refer to the official OASIS DITA Documentation.
